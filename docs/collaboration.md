1. 브랜치 격리 원칙 (main 직푸시 절대 금지)
지킬 규칙: 모든 작업은 feature/파트-기능명 브랜치에서만 작업하고, 무조건 dev로 PR을 쏩니다.

2. 최소 1인 승인(Approve) 후 머지
지킬 규칙: 본인이 PR 올리고 본인이 머지하지 않습니다. 팀원 4명 단톡방에 "PR 올렸으니 확인 부탁해" 올리고, 다른 팀원이 깃허브에서 초록색 [Review changes ➔ Approve] 버튼을 눌러준 뒤 머지합니다.

3. 단순하고 일관된 커밋 접두사 (단 3개만 사용)
규칙이 6~7개면 무조건 깨집니다. 딱 3개만 씁니다.
feat: 새로운 기능 추가 
fix: 버그나 오류 수정  
docs: 문서/기획 수정
+ 파일 추가
- 파일 삭제
* 파일 변경

4. .env 커밋 절대 차단 (레포지토리 생성 즉시 1회 작업)
지킬 규칙: 첫 커밋 때 .gitignore에 .env와 .env.local을 무조건 포함시킵니다.
공유 방식: 깃허브에는 값 없는 env.example만 올립니다.
